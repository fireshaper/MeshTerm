# MeshTerm — Map View Plan

Plan for `map-view-spec.md` (pasted by the user on 2026-10-20). The spec's tile proxy reference (`dashboard-spec.md` §4) is MeshTerm's existing `/api/tiles` proxy (dashboard phase D3). Same rules as the other plans: each step done when its tests pass and the full suite stays green; stop after each phase; record choices in `DECISIONS.md`; commit and push after each finished change (user's standing instruction, 2026-10-20).

## Phase A — the core page (build first) — done 2026-10-20

| Step | Work                                                                                                                                                                                                                                                                                                                                                                                                                                         | Tests                                                                                                                                        |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| A1   | Tile proxy per the OSM policy: at most 2 upstream requests at once (queued), `Expires` honoured as well as `Cache-Control`.                                                                                                                                                                                                                                                                                                                  | Concurrency cap with a slow fake upstream; `Expires` TTL.                                                                                    |
| A2   | `GET /api/connections/:id/map/nodes?since=` → GeoJSON points for every node with a stored position (all time by default), properties per spec §5, plus foreign members `unplaced` (nodes without a position) and `thresholds`.                                                                                                                                                                                                               | Route test on the `dashboard` scenario: features, properties, precision radius, `since`, unplaced.                                           |
| A3   | `/map` route (lazy-loaded chunk with MapLibre 6.12.0, CSP-safe module worker) and a "Map" nav item. Raster OSM base through `/api/tiles`, always-visible attribution. GeoJSON source with clustering (radius 50, max zoom 13, cluster color = best status inside). Node dots colored by status from `--mt-map-*` tokens (read from CSS), self larger with a ring, favorites starred; labels drawn as canvas images (no glyph server needed). | Pure modules: feature building and status ranks, cache patches, viewport storage.                                                            |
| A4   | Popup on marker click (long/short name, ID, last seen, battery, hops, Details → node drawer); zoom +/−, Fit all, My node; fit to all markers on first visit, remembered viewport after; `?node=` deep link (dashboard mini maps link here); "Not on map (N)" list; live updates from `node.upsert`/`position.new` with `setData` at most once per second.                                                                                    | Component tests for controls and lists; e2e: nav → map, markers rendered, popup, fit, not-on-map list, live move, no CSP violations, 390 px. |

Phase A acceptance (spec §0): open `/map` from the nav and see every node with a known position on an OpenStreetMap base; pan and zoom anywhere; click any marker for its info.

## Phase B — later, in the spec's order

Node side panel + search, time range filter, neighbor links (data exists since O3: `neighbors`), traceroute paths (needs the traceroute feature), position trails, measure tool, range rings, then offline vector maps and coverage heat. Theme `map-style.json` support and the remaining tokens/hooks come with them.
