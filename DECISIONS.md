## Phase 2

| Step | Decision                                                                                                                                                                                                                                                                                                                     | Reason                                                                                                                         |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 2.1  | `@meshtastic/protobufs` is pinned to **2.8.1 from JSR** (`jsr:2.8.1`). npm's newest is 2.8.0. `@bufbuild/protobuf` **2.16.0** is a direct, exact dependency because we call `create`/`toBinary`/`fromBinary`/`fromJson` ourselves.                                                                                           | Newest release; the registry rule says JSR when npm lacks that version.                                                        |
| 2.1  | The codec and stream framer were first written in `packages/fake-node`; Step 3.1 moved them to `@meshterm/protocol` (see Phase 3).                                                                                                                                                                                           | Avoid shaping a shared module before the server's needs were known; keep protobufs out of `@meshterm/shared` (browser bundle). |
| 2.2  | On a length over 512 the framer drops one byte and rescans. A lone trailing `0x94` is kept for the next chunk. Zero-length frames are dropped (changed in Step 3.2 to match its test; originally they decoded as an empty `ToRadio`).                                                                                        | Matches the firmware's resync behavior.                                                                                        |
| 2.3  | The handshake reply follows the **firmware's** PhoneAPI order: my_info, own node_info, metadata, channels, config, module config, other node_infos, `config_complete_id`. The plan listed other nodes before metadata.                                                                                                       | Clients should be tested against the real order.                                                                               |
| 2.3  | Scenarios are JSON in `packages/fake-node/scenarios/` (built-ins `default` with 3 neighbors, `busy` with 7). Protobuf parts use proto-JSON and are parsed with `fromJson`, so unknown fields fail loudly. Nodes may carry `lastHeardAgoS`, turned into `lastHeard` at send time.                                             | Swappable meshes with no hand-written protobufs; fresh timestamps.                                                             |
| 2.3  | The scenario's own node is `0xa1b2c3d4` and a neighbor is `0x0badcafe`, matching `@meshterm/shared` fixtures. Every `FromRadio` gets an increasing `id`, like firmware.                                                                                                                                                      | Consistent test data across packages.                                                                                          |
| 2.4  | `injectNodeInfo` delivers a `NODEINFO_APP` mesh packet (a `User` payload), not a `FromRadio.node_info`, and updates FakeNode's NodeDB so the next handshake includes the node.                                                                                                                                               | Outside the handshake, firmware forwards node announcements as mesh packets.                                                   |
| 2.4  | Every inbound mesh packet gets a `queueStatus` reply naming its id (as firmware does). Text packets then get a routing reply per ack mode: `ack` = `errorReason NONE`, `nak` = `MAX_RETRANSMIT`. A DM is acked "from" the recipient, a broadcast from our own node. `setAckMode(mode, delayMs)` can delay the routing reply. | Realistic inputs for the `queued → sent → acked/failed` flow in Phase 7.                                                       |
| 2.4  | `reboot(downMs)` closes the listener (so connects get `ECONNREFUSED`), then re-listens on the same port, and increments `myInfo.rebootCount`. Injected packet ids come from a counter starting at `0x10000000`.                                                                                                              | A real refused connection; ids are unique and predictable.                                                                     |
| 2.5  | Audit classes: `handshake` (`want_config_id`, `disconnect`), `heartbeat`, `transmit` (every `packet`, even one addressed to the local node, and `mqttClientProxyMessage`), `other` (XModem, empty).                                                                                                                          | Conservative: anything that could leave over the air counts.                                                                   |

## Phase 3

| Step | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Reason                                                                                                                                                                                                                                                                                                                                               |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 3.1  | **Don't use `@meshtastic/transport-node` (0.0.2) or `@meshtastic/core` (2.6.7).** Our own `TcpTransport` uses our framer.                                                                                                                                                                                                                                                                                                                                    | transport-node was last published 2025-09. It pins core 2.6.7, which bundles its own older protobufs (two copies, mismatched types against 2.8.1). Core's framer has no >512 resync, stalls on a stray `0x94`, and discards valid payloads that contain `0x94 0xC3`. Its socket timeout is an idle timeout, not a connect timeout. Both are GPL-3.0. |
| 3.1  | New package **`@meshterm/protocol`** (`packages/protocol`) holds the codec and framer and is the only package that depends on `@meshtastic/protobufs` and `@bufbuild/protobuf`. It re-exports the protobuf namespaces (`Mesh`, `Portnums`, `Config`, …) and the bufbuild helpers. `fake-node` and `server` import from it.                                                                                                                                   | One shared framer (the plan says share, don't copy) and a single pin point for protobufs; keeps protobufs out of `@meshterm/shared`.                                                                                                                                                                                                                 |
| 3.1  | `Transport` extends Node's typed `EventEmitter<TransportEvents>` (`open`, `fromRadio`, `close {reason, error}`, `error`) and has `isOpen`, `connect()`, `disconnect()` and `send(ToRadioInit)`. Instances are **single-use**. A failed `connect()` rejects and emits nothing. `close` fires once only when the link ends without `disconnect()`. Nothing is emitted after `disconnect()`. `error` is informational and is only emitted when someone listens. | Lets `NodeConnection` (Phase 4) treat "close" as the one failure signal and build a new transport per attempt via the factory.                                                                                                                                                                                                                       |
| 3.1  | The contract suite (`describeTransportContract`) takes a harness that controls the peer (send a `FromRadio`, read what it received, close from its side, count connections, make an unreachable transport). FakeNode gained `sendFromRadio()` and `dropClients()` for this. `@meshterm/fake-node` is a server devDependency.                                                                                                                                 | One suite for mock, TCP and later HTTP transports.                                                                                                                                                                                                                                                                                                   |
| 3.2  | New config: `MESHTERM_CONNECT_TIMEOUT_MS` (default 10 s) and `MESHTERM_TCP_KEEPALIVE_MS` (default 15 s, the idle time before OS keepalive probes). No-delay is on.                                                                                                                                                                                                                                                                                           | A node on the LAN answers in milliseconds; 10 s tolerates Wi-Fi power-save. Keepalive spots a dead link that sends no FIN.                                                                                                                                                                                                                           |
| 3.3  | Heartbeat default stays **60 s** (`MESHTERM_HEARTBEAT_INTERVAL_MS`). `Heartbeat` is a separate class that sends only while `transport.isOpen` and stops on `close`. Phase 4 decides when to start it.                                                                                                                                                                                                                                                        | The firmware drops API clients that are idle for 15 minutes (noted in `@meshtastic/core`). 60 s is far inside that, and a write on a dead link fails sooner. Heartbeats never reach the mesh.                                                                                                                                                        |

## Phase 4

| Step | Decision                                                                                                                                                                                                                                                                           | Reason                                                                                                                                            |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4.1  | Time goes through an injectable `Clock` (`now()`, `setTimer(ms, fn) → cancel`) with a manual `FakeClock` for tests, instead of Vitest's global fake timers. `Heartbeat` uses it too (its 3.3 test now drives a `FakeClock`). Randomness is an injectable `() => number`.           | Tests can drive timers by hand while FakeNode's real sockets keep running; global fake timers would also freeze FakeNode and the polling helpers. |
| 4.1  | Transitions live in `ALLOWED_TRANSITIONS` inside a small `ConnectionStateMachine` that `NodeConnection` wraps. `disconnected → disconnected` isn't a transition: `stop()` when already disconnected is a no-op with no event.                                                      | One table to test; "every state → disconnected" in the plan means every _other_ state.                                                            |
| 4.2  | The `want_config_id` nonce is a random uint32 from 1 to 0xFFFFFFFF that skips **69420 and 69421**.                                                                                                                                                                                 | Firmware reads those as "config only" and "nodes only" requests and would send a partial reply.                                                   |
| 4.2  | New config `MESHTERM_CONFIG_TIMEOUT_MS`, default **30 s**.                                                                                                                                                                                                                         | A large NodeDB over slow Wi-Fi can take several seconds; 30 s still recovers quickly from a hung node.                                            |
| 4.2  | The handshake fills a _pending_ model that replaces the current one only when the matching `config_complete_id` arrives. Once connected, `myInfo`/`metadata`/`nodeInfo`/`channel` messages update it. Every `FromRadio` is also re-emitted as `fromRadio` for the Phase 6 decoder. | A half-finished handshake never leaks into the model. Per the source-of-truth decision, Phase 5/6 makes this a write-through cache over SQLite.   |
| 4.2  | FakeNode gained `setConfigCompleteMode("echo"                                                                                                                                                                                                                                      | "wrong"                                                                                                                                           | "none")`; MockPeer gained an `onReceive` hook (used to script a handshake reply). | The "wrong id" variant the 4.2 test asks for; handshake-capable unit tests without sockets. |
| 4.3  | Backoff = `min(max, min × 2^failures × (1 ± 0.2))`, i.e. **±20 % jitter**, capped _after_ jitter. A random value of 0.5 gives the exact doubling sequence. `failures` resets on reaching `connected`. A `retry` event reports `{failures, delayMs}`.                               | Spreads simultaneous reconnects (e.g. after a router reboot) without exceeding the 60 s cap.                                                      |
| 4.3  | A failed attempt in any active state (connect rejected, link closed, config timeout, send failure) goes to `reconnecting` and schedules the next attempt. The heartbeat starts only on `connected`, and every exit tears down the heartbeat, config timer and transport.           | One failure path; never gives up.                                                                                                                 |

## Phase 5

| Step | Decision                                                                                                                                                                                                                                                                                                                   | Reason                                                                                                                                                                                                      |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 5.1  | `better-sqlite3` **13.0.3**, `drizzle-orm` **0.45.4**, `drizzle-kit` **0.31.11** (stable lines, not the 1.0 RCs). `better-sqlite3` is allowed to run its install script via `onlyBuiltDependencies` in `pnpm-workspace.yaml`. Pragmas: WAL, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout=5000`.                  | pnpm 10 blocks install scripts by default. NORMAL is the recommended durability level with WAL. On this machine it compiled from source (node-gyp), so the Docker build stage needs build tools (Phase 10). |
| 5.2  | Migrations live in `apps/server/drizzle/` (excluded from Prettier) and are applied by `initDatabase()` (open → migrate → seed). Phase 7's entry point calls it.                                                                                                                                                            | There is no server entry point yet; one function keeps "on every start" testable.                                                                                                                           |
| 5.2  | Extra columns beyond the plan: `connections.source` (`env`/`user`) and `settings.updated_at`. Foreign keys cascade on connection delete. Node `!hex` ids are derived from `num`, not stored.                                                                                                                               | `source` identifies the env-seeded row for 5.3. Nothing should outlive its connection.                                                                                                                      |
| 5.3  | Env seeding: no rows → insert one `source='env'` row named "Primary node". An env row exists → update its host/port in place when they change (same id, so history stays attached). Only user rows → do nothing.                                                                                                           | The plan's recommendation. Changing an IP in compose shouldn't orphan history or create a second node.                                                                                                      |
| 5.4  | The pagination cursor is **`(rxTime, id)`**, not a bare timestamp. Order is `rx_time DESC, id DESC`, and `nextCursor(page, limit)` builds the cursor. `limit` outside 1–200 throws `RangeError` (default 50). Channel lists only include broadcasts (`peer IS NULL`). DM lists match `peer`, which covers both directions. | Firmware `rx_time` has one-second resolution, so many messages share a timestamp and a `< before` cursor would skip them at page boundaries. Phase 7 encodes the cursor as one query param.                 |
| 5.4  | `upsertNode` overwrites every field with what it is given.                                                                                                                                                                                                                                                                 | Merge rules (e.g. don't clobber `last_heard` with null) belong in the Phase 6 persistence subscriber, which knows what each packet actually told us.                                                        |
| 5.5  | Dedupe is the unique index `messages_dedupe_idx` (`connection_id`, `from_num`, `packet_id`) in its own migration, plus `INSERT … ON CONFLICT DO NOTHING` on that target. The first copy heard is kept. A reused message `id` still throws.                                                                                 | The confirmed design. The first copy has the most direct signal values. A UUID collision is a bug, not a duplicate.                                                                                         |

## Phase 6

| Step | Decision                                                                                                                                                                                                                                                                                                                     | Reason                                                                                                                                                                                                                       |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 6.1  | `EventHub` is synchronous, delivers in subscription order, snapshots the subscriber list per publish (unsubscribing mid-delivery is safe), and has `subscribeAll` for the coming WS fan-out. Errors go to an injected `Logger` (a Pino-compatible interface; Pino itself arrives with Fastify in Phase 7).                   | Simple and deterministic; persistence finishes before the next event.                                                                                                                                                        |
| 6.2  | The decoder emits **internal `radio.*` events**, not the WS events. The persistence subscriber turns them into `node.upsert` / `message.new` / `message.status` / `channel.upsert` after writing.                                                                                                                            | A routing reply only names the _packet_ id, so the message UUID comes from the database. Duplicates must be dropped before anything reaches browsers (6.3).                                                                  |
| 6.2  | "Heard" updates (`last_heard`, SNR, hops = `hop_start - hop_limit`) come from a separate pure `nodeHeard()` applied to **every** packet, including ignored ports and encrypted payloads.                                                                                                                                     | Satisfies both 6.2 ("an unhandled port yields no events") and 6.3 ("any packet updates last_heard").                                                                                                                         |
| 6.2  | DM vs channel: `to == 0xFFFFFFFF` → channel message (`peer` NULL); anything else → DM with `peer = from`. Firmware `rx_time` (s) → ms, or receive time when it is 0. `rx_snr`/`rx_rssi` both 0 → NULL (never crossed the air).                                                                                               | The plan's rule; firmware only forwards DMs addressed to us.                                                                                                                                                                 |
| 6.2  | Enum values become names (`HELTEC_V3`, `ROUTER`, `MAX_RETRANSMIT`, …) via a helper that returns NULL for values this protobufs version doesn't know. Channel names are stored raw: an empty primary name is _not_ replaced with the modem preset name ("LongFast") here.                                                     | Newer firmware may send new enum values. The display name is a UI concern (needs LoRa config).                                                                                                                               |
| 6.2  | Decoder fixtures are captured from FakeNode at test time (`recordFrames()`), not stored as files.                                                                                                                                                                                                                            | Always in step with FakeNode and the protobufs version. Real-node captures can be added as files once a node is available.                                                                                                   |
| 6.3  | New column `connections.my_node_num` (migration 0002), written on `my_info`.                                                                                                                                                                                                                                                 | The Phase 7 snapshot is built from SQLite and needs it.                                                                                                                                                                      |
| 6.3  | Node merge rules: absent fields keep their stored value; `last_heard` never moves backwards; `snr`/`hops_away` only come from updates at least as recent as the stored `last_heard`. A packet from an unknown node creates a placeholder row.                                                                                | Handshake NodeDB entries can be older than packets already heard.                                                                                                                                                            |
| 6.3  | Status rules: `acked` is final; a routing reply for a packet we didn't send is ignored (debug log). An ACK whose `from` is our own node (an implicit ACK: a neighbour rebroadcast it) also counts as `acked`.                                                                                                                | The status enum has no "relayed" state yet.                                                                                                                                                                                  |
| 6.3  | Source of truth: `NodeConnection.model` remains the protocol-level handshake buffer. Everything it holds about nodes and channels is persisted through the hub, and all client-facing reads (REST, WS snapshot) will come from SQLite. It is **not** hydrated from SQLite at boot, because nothing reads it for client data. | Meets the intent of the confirmed decision (SQLite is authoritative; the model never holds anything SQLite doesn't) without a second copy to keep in sync. Revisit if a consumer needs node data before the first handshake. |

## Phase 7

| Step | Decision                                                                                                                                                                                                                                                                                                                                               | Reason                                                                                                                                                                                                                    |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 7.1  | `fastify` 5.12.7, `@fastify/websocket` 11.3.4, `fastify-type-provider-zod` 7.0.0, `@fastify/rate-limit` 11.2.1, `ws` 8.22.0 (runtime: the gateway uses it), dev `tsx` 4.23.15 and `tsup` **8.5.1** (not 9.0.0, a new major released five days ago). `esbuild` added to `onlyBuiltDependencies`.                                                        | Latest stable lines; esbuild's postinstall is its official binary check.                                                                                                                                                  |
| 7.1  | `buildApp` never listens. It takes `deps.database` (tests pass `:memory:`), runs migrate + seed itself, and starts connections on `onReady`. The process binds `0.0.0.0`.                                                                                                                                                                              | Tests use `app.inject` or `listen({port: 0})`. 0.0.0.0 is required inside Docker.                                                                                                                                         |
| 7.1  | The bundle is `dist/main.js` (ESM, node24). `@meshterm/*` (and through them protobufs) are bundled; npm dependencies stay external. The migrations folder is found at runtime relative to the module (`src/db/` or `dist/`).                                                                                                                           | Workspace packages export TypeScript source. The Docker image needs `dist/`, `drizzle/` and production `node_modules`.                                                                                                    |
| 7.1  | Errors are `{error, message}` with codes `bad_request`, `not_found`, `not_connected`, `rate_limited`, `internal_error` (5xx messages are generic and the detail is logged). Handlers throw `HttpError` instead of returning `reply`.                                                                                                                   | One shape for the web client. Fastify's types reject sync handlers that return either a value or a reply.                                                                                                                 |
| 7.3  | Message pages: newest first; `before`/`nextCursor` is the opaque string `<rxTime>_<id>` (see 5.4). `/api/connections` adds `state` and `myNodeNum`. Response schemas use the shared Zod types, so unknown keys (e.g. a PSK) are stripped on the way out too.                                                                                           | Defense in depth on the PSK rule.                                                                                                                                                                                         |
| 7.4  | Snapshot = nodes, channels, and the last **50** messages per non-disabled channel and per DM peer, oldest first; older history comes from REST. An unknown connection id in `subscribe` gets an `unknown_connection` error frame. Non-JSON → `bad_json`, schema mismatch → `bad_message`; the socket stays open.                                       | Bounded snapshot size.                                                                                                                                                                                                    |
| 7.5  | `channel.upsert` and `radio.*` events are not forwarded (not in the WS protocol); channels arrive with snapshots.                                                                                                                                                                                                                                      | Keeps the protocol as defined in 1.3.                                                                                                                                                                                     |
| 7.6  | "Sent" = the frame was written to the node socket without error (not the firmware's `queueStatus`). DMs go out on channel index 0 with `want_ack`. A write that throws marks the message `failed` and still returns 201 with that status. The ACK timer (`MESHTERM_ACK_TIMEOUT_MS`, default 120 s) only fails messages that are still `queued`/`sent`. | The plan's definition. Clients always get the stored message back.                                                                                                                                                        |
| 7.6  | `to` may not be 0 or `0xFFFFFFFF`; broadcasts use `channel`.
